# Git: База для собеседования

## Что такое Git?
Распределенная система контроля версий (DVCS). В отличие от SVN, у каждого разработчика есть полная копия истории.

## 5 главных команд (из Roadmap):
1. `git init` — инициализация репозитория.
2. `git add <file>` — добавление в staging area.
3. `git commit -m "msg"` — фиксация изменений.
4. `git push` — отправка в удаленный репозиторий.
5. `git pull` — получение изменений из удаленного репозитория.

## Best Practices (Google/Meta style):
* **Conventional Commits:** `feat:`, `fix:`, `docs:`, `chore:`.
* **Атомарные коммиты:** Один коммит = одна логическая задача.
* **Никогда не коммитить секреты:** Использовать `.gitignore` и `.env` файлы.
* **Ветвление:** Trunk-based development (короткоживущие ветки, частые мержи в main) — современный стандарт DevOps.

## Частые вопросы на собеседовании:
* В чем разница между `git fetch` и `git pull`? (`fetch` скачивает, но не мержит, `pull` = `fetch` + `merge`).
* Что такое `git rebase` и чем он отличается от `merge`? (Rebase переписывает историю, делая её линейной, merge создает коммит слияния).
* Как откатить коммит? (`git revert` — безопасно, создает новый коммит; `git reset` — опасно, переписывает историю).
